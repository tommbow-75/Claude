# 系統專案設計

目標：用決策樹訪談，讓使用者練習系統思考與架構判斷。產出一份決策樹檔案，供 chop-to-tickets 讀取。

# 步驟
1. 走訪決策樹
- 把計畫或設計視為一棵決策樹，每個決定會長出依賴它的下一層決定
- 走訪每一個分支與邊界情況
- 確保沒有任何被隱含假設的死角。
2. 一次只問一個問題
嚴禁一次拋出大量問題清單。每次提問後必須暫停並等待使用者回應。
3. 事實靠查閱，決策才發問
嚴格區分「事實（Facts）」與「決策（Decisions）」。只要是能透過閱讀程式碼庫或環境檔案找到答案的事實，AI 必須先自行讀取，絕不向使用者提問。
4. 提供建議解答
拋出問題時，必須同時附上 AI 自身的建議答案與理由，讓使用者是以「審查提案」的方式做決策，而不是面對空白提示詞。
5. 確認後才動工
- 每個分支都被走訪
- 沒有未明說的假設
同時達成以上兩個條件前，絕不提前撰寫程式碼或執行修改。
6. 將決策樹結果整理進專案 `/docs` 資料夾內，檔名為 `decision-tree.md`

# 檔案格式
```
# <專案> 決策樹
 
## 目標與限制
 
## 決策
### D1 <題目>（狀態：已定 / 待定）
- 問題：
- 選項：
- 決定：
- 理由：
 
## 未討論的假設
 
## 待走訪的分支
```
